# Publishing Strategy

## Best Publishing Time
Tuesday-Thursday, 9-11am ET, consistent with channel pattern. The paradox hook ("died but the
code won") is self-contained and evergreen — no urgency premium, hold for the best day/time slot.

## Target Audience
Developers who used Parse.com or currently run Parse Server; founders/PMs evaluating open-core or
acquired-platform risk; general audience of this channel drawn to a rarer, more upbeat entry in
the catalog.

## Playlist
Add to "Startup Autopsies" playlist. Also strong fit for a potential future "Open Source Risk" or
"Good Endings" playlist alongside package 019 (Cyanogen/Docker/MongoDB-Elastic) if that theme gets
revisited — note 019 and 049 illustrate opposite mechanisms (open source killing a company vs. a
company's death freeing its open-source code to thrive), which makes them a strong paired
recommendation, not a duplicate.

## End Screen
Most recent autopsy + subscribe element. Consider a direct card to package 046 (Mailbox) as an
explicit "same category, opposite outcome" cross-reference — both are acqui-hire stories with
very different endings.

## Cards
Card at the "STILL ACTIVELY MAINTAINED — 2026" title card (end of Segment 8, ~8:45) linking to the
"Startup Autopsies" playlist for viewers hooked by the reveal; card at the mid-video CTA (~9:45)
reinforcing the "this one has a good ending" framing as distinct from the channel's usual stories;
optional third card at the Mailbox cross-reference beat (~9:30) linking directly to package 046's
video for viewers who want the contrasting story immediately.

## End CTA
"Subscribe if you want the next autopsy in the library — most of them don't end this well, but
some do, and I want to keep finding both kinds. If you ever built on Parse or migrated to Parse
Server, tell me what that was actually like in the comments."
